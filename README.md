# nwjjyy 1.0

一个放在 NFC 挂件背后的兔子互动小世界。用奶白色、淡紫色和浅粉色，收藏一些慢慢补上的声音与记忆。

主角使用你提供的奶白色毛绒垂耳兔模型图。摸摸它，它会双脚小碎步，冒出「你咋这样！」；短时间连续摸三下，还有一个小彩蛋。网页保留原图中的紫色刺绣，字样为小写 `nwj jyy`，网站显示名使用 **nwjjyy**。

本项目使用 HTML、CSS、原生 JavaScript，无后端、无数据库、无付费 API，也不需要访客注册或安装 App。本地浏览无需构建；托管发布只复制静态文件。当前照片、录音和纪念日均为明确占位，未包含真实个人资料。

## 本地预览

最直接的方法是用浏览器打开根目录的 `index.html`。兔子互动和默认占位内容不需要本地服务器。

建议在修改资源后通过 HTTP 预览。在此项目目录打开 PowerShell，运行：

```powershell
python -m http.server 8080 --bind 127.0.0.1
```

然后访问 [本地预览](http://127.0.0.1:8080/)。关闭预览时，在运行服务器的终端按 `Ctrl+C`。若端口被占用，改为 `8081`，网址也改为对应端口。该命令需要已安装 Python；Python 仅用于本地预览，正式网站不依赖它。

在桌面浏览器的开发者工具中开启手机设备模拟，可以先检查竖屏布局；发布后仍应使用实际 iPhone 与 Android 手机检查点击、音频和 NFC 打开流程。

## 修改文字与记忆

日常内容集中在 `site-config.js` 的 `window.SITE_CONFIG`。保留 JavaScript 对象的括号、引号与逗号，修改已有值即可；修改后刷新页面预览。

| 配置项 | 用途 |
| --- | --- |
| `title` | 网站名称 |
| `welcome`、`subtitle` | 首页欢迎语与辅助文字 |
| `bunny` | 普通互动与隐藏彩蛋的气泡文字 |
| `audio` | 音频是否启用、文件路径、标题和占位提示 |
| `memories` | 照片、替代文字、标题与说明 |
| `note` | 一段文字记录的标题与正文 |
| `anniversary` | 纪念日名称与日期 |

修改照片时，先把获得公开授权的图片放入 `assets/images/`，再修改对应的照片配置。例如：

```javascript
{
  image: 'assets/images/our-photo.jpg',
  alt: '这张照片的简短描述',
  title: '照片标题',
  caption: '这里写你希望保留的文字。'
}
```

`image` 留空时显示原创占位画面；图片加载失败时也会显示占位。建议先在手机上确认裁切效果，再压缩大图，避免通过 NFC 打开时等待太久。文件名建议使用小写英文、数字和短横线，避免空格及大小写混用。

纪念日日期使用 `YYYY-MM-DD` 格式，例如下面仅展示格式，不代表真实日期：

```javascript
anniversary: {
  date: '',  // 填入你确认的真实日期；留空显示待填写
  title: '我们的纪念日'
}
```

文字记录在 `note.title` 与 `note.text` 中修改。当前占位文案不代表已经发生的经历；加入真实内容前，请自行核对并确认公开范围。

## 添加真实录音

当前音频默认关闭，页面显示「等一段特别的声音到来。」。没有自动播放，也没有合成录音或伪造人声。未启用时不会请求不存在的 MP3 文件。

添加步骤：

1. 确认录音相关人员同意公开，且你有权使用该录音。
2. 将 MP3 文件放到 `assets/audio/ni-za-yang.mp3`。
3. 将音频配置中的 `enabled` 改为 `true`，保留或更新相对路径。

```javascript
audio: {
  enabled: true,
  path: 'assets/audio/ni-za-yang.mp3',
  title: '听听我们的声音',
  emptyText: '等一段特别的声音到来。'
}
```

播放器支持手动播放、暂停、继续和进度调整。启用后若文件丢失、无法解码或加载失败，会回到占位提示。移动浏览器可能限制没有用户操作的播放，因此需要实际点击播放按钮；网站不会绕过这项限制。

## 互动说明

- 点击兔子或「摸摸小兔子」，触发小碎步与「你咋这样！」。
- 在约 1.4 秒内连续触发三次，出现「被你发现啦！」和小惊喜。
- 动画会恢复初始姿势，可以反复触发。
- 键盘用户可以使用 `Tab` 聚焦互动按钮，再按 `Enter` 或空格触发。
- 系统开启「减少动态效果」时，页面会简化动画，气泡反馈仍然保留。

页面以你提供的模型图为主角，没有用 Emoji 或另一只新绘兔子替换它。透明 PNG 经内置 ImageGen 去除白色背景、地板阴影并清理外围白色碎屑，保留奶白毛绒质感、垂耳外形和原图紫色刺绣。来源与处理约束见 [图像说明](assets/images/ASSET_NOTES.md)。

动画通过内联 SVG 的裁切区域重复引用同一张 PNG，将身体、双耳、双脚和眼睛区域分层，再用 CSS 进行双脚交替小碎步、双耳轻摆和眨眼。这是基于静态模型图的二维动画；修改模型图片时，需要同步调整 `index.html` 中的裁切区域与 `style.css` 中的动作参数，并重新检查分层接缝和动作效果。

以下是手动发布教程，不表示已经发布。先在本地确认内容，再由仓库所有者执行。

### 1. 创建仓库并上传

登录 GitHub，选择 **New repository**，仓库名可填写 `nwjjyy`。GitHub Free 的 Pages 通常使用公开仓库；选择公开之前，确认项目内没有私人照片、录音或其他敏感内容。创建仓库后，通过 **Add file → Upload files** 上传项目文件及 `assets` 文件夹，并提交到 `main` 分支。不要上传本地 `.git` 文件夹、临时截图、日志或个人资料。仓库首页应直接看到 `index.html`。[GitHub 官方创建站点说明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

也可以使用 Git 客户端上传；不熟悉命令行时，网页上传即可满足本项目需求。

### 2. 开启 Pages

进入仓库 **Settings → Pages**，在 **Build and deployment** 中将 **Source** 设为 **Deploy from a branch**，选择已存在的 **main** 分支和 **/(root)**，点击 **Save**。若你的实际分支名不同，请选择存放本项目文件的那一支。后续提交到该来源后，Pages 会重新部署；可在仓库 **Actions** 中查看进度或错误。[GitHub 官方发布来源设置](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

### 3. 获取稳定 HTTPS 地址

部署完成后，在 **Settings → Pages** 点击 **Visit site**，以页面给出的地址为准。普通项目仓库的地址通常类似：

```text
https://你的用户名.github.io/nwjjyy/
```

这是格式示例，不是本项目已发布的地址。使用 `github.io` 域名的新 Pages 站点自动支持 HTTPS；在 Pages 设置中确认 **Enforce HTTPS** 已启用。所有资源均使用相对路径，不要把图片或脚本换成 HTTP 绝对地址，避免混合内容问题。[GitHub 官方 HTTPS 说明](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https)

### 4. 更新内容，保持网址不变

在同一仓库、同一发布分支中修改文件并提交即可。更新照片、录音、文字、样式和互动通常不需要改变网址，也不需要重写 NFC。更新后先等待部署完成，再刷新浏览器；旧内容仍显示时，可使用无痕窗口检查缓存。为了保持 NFC 入口稳定，避免随意修改 GitHub 用户名、仓库名、发布目录或域名。

### 5. 路径与发布排查

| 现象 | 优先检查 |
| --- | --- |
| 整个站点 404 | Pages 来源分支是否正确，`index.html` 是否在所选根目录，部署是否成功 |
| 页面有文字但没有样式 | 是否漏上传 `style.css`，文件名大小写是否完全一致 |
| 图片或音频打不开 | 配置路径是否相对、文件是否上传、扩展名与大小写是否匹配 |
| 新内容没有出现 | Actions 部署是否结束、是否提交到发布分支、浏览器是否仍使用缓存 |
| 主域访问正常，仓库地址异常 | 是否把资源路径写成了 `/assets/...` 这类站点根路径 |

本项目使用 `./style.css`、`./script.js` 和 `assets/...` 形式的相对地址，兼容 `https://用户名.github.io/仓库名/` 子路径。新增资源也应遵循这个规则，不要写本地磁盘路径、`localhost` 地址或以 `/` 开头的资源路径。

## 写入 NTAG215 NFC 挂件

先确定最终公开 HTTPS 地址，并在手机浏览器中确认它可以直接打开。`127.0.0.1`、`localhost` 和本地 `file://` 地址只适用于开发，不能作为挂件入口。

使用 wakdev 的 NFC Tools 写入一个网址记录：

1. 打开 NFC Tools，进入 **Write／写入**。
2. 选择 **Add a record／添加记录**，再选择 **URL / URI**。
3. 输入最终 HTTPS 地址并确认；如果 App 把协议与网址分开显示，核对合成结果只有一个 `https://`。
4. 返回写入界面，确认只保留预期的网址记录，点击 **Write／写入**（可能显示字节数）。
5. 将手机 NFC 感应区域贴近 NTAG215，保持稳定，等待写入成功。

不同版本与语言的按钮文字可能略有差异，流程以 App 实际界面为准。[NFC Tools 官方网址写入教程](https://www.wakdev.com/en/knowledge-base/how-to-guides/how-to-write-a-link-url-on-an-nfc-chip.html)

写完后关闭写入界面，用实际手机重新感应挂件，按系统提示打开网址，再测试兔子与播放器。iPhone、Android 的 NFC 感应位置和提示方式不同，部分设备需要先开启 NFC、解锁或点击系统通知；请以实际设备表现为准。

NFC 标签只保存并打开网站网址。兔子动画、照片和音频都由浏览器处理，网站不调用浏览器 NFC API；访客不需要安装本网站专用 App。尚未确认最终地址时，请不要使用标签的永久锁定功能。只要网址保持不变，网页内容更新后通常无需重新写标签。
